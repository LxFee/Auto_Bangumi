# 确定既有媒体文件的命名计划回填策略

## Question

升级后如何从现有下载任务和当前文件路径生成命名计划，区分已经由 AutoBangumi 命名的文件与原始文件，并在缺少历史解析数据时避免误判为手动修改？

## Resolution

既有文件采用“中性基线、禁止升级即批量改名”的回填策略：

- 仅为当前可关联到成员规则、且下载器已经返回真实文件列表的任务回填；身份使用 AutoBangumi 下载任务身份与下载器文件序号，元数据尚未就绪时不创建占位计划。
- 将下载器当前路径保存为既有命名基线，并从当前文件名生成缺省解析快照；基线既不标记为手动纠错，也不证明它由 AutoBangumi 命名。
- qBittorrent 的终态改名标签及 aria2 的 `renamed_paths` 只用于记录“曾由 AutoBangumi 处理”的历史来源，不把当前文件名反推成手动字段。
- 回填计划只生成预览，不因升级而自动应用。用户明确应用后才产生已确认修订；升级后新发现的下载任务继续遵循正常自动命名流程。
- 下载器离线、任务消失、文件序号缺失或关联不唯一时跳过并记录可重试原因；后续发现周期继续回填，不把暂时不可见当作删除。
- 回填按媒体文件身份幂等，重复执行更新发现状态但不覆盖缺省解析快照、手动值或已确认修订。
