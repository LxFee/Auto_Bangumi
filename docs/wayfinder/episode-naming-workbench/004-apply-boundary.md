# 确定手动应用的原子边界与失败恢复

## Question

应用一份手动命名计划时，视频与匹配字幕应以什么边界执行、遇到目标冲突或部分失败时保留什么状态，并如何安全重试或恢复缺省？

## Resolution

- 一个视频及其匹配字幕组成一个命名单元，是应用、冲突检查和失败恢复的最小边界。
- 应用前计算并预留单元内所有目标；任一字段异常或不可接受的目标冲突都会阻止该单元开始执行。
- 下载器调用采用持久化的前向恢复：每完成一个文件立即记录进度，部分失败不回滚已完成文件，只重试剩余步骤。
- 所有视频和字幕都经过下载器状态校验后，才把当前计划修订标记为已应用；中途失败统一显示“应用未完成”及具体文件原因。
- 目标已经属于同一媒体文件时视为已完成；目标属于其他文件时绝不直接覆盖，并以命名异常阻止该单元。
- 真正的 V2/V3 替换继续使用现有版本冲突策略；只有用户明确配置 `replace` 时才执行安全替换，否则保留双方等待处理。
- “恢复缺省”先生成采用缺省字段的新预览，用户应用成功后才删除手动覆盖；失败时保留原手动值和可恢复的新修订。
- 点击应用后先持久保存已确认修订，再立即触发执行；短时间内完成则直接反馈，下载器缓慢或离线时页面结束等待，后台继续安全重试。
- 已确认修订在页面刷新或进程重启后继续存在，用户看到相同目标、进度和失败原因。
