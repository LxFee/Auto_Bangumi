# 确定命名计划的生成与存续周期

## Question

命名计划应在何时生成和刷新，如何识别改名前后的同一媒体文件，以及下载任务消失或解析器升级后缺省值与手动值分别如何存续？

## Resolution

- 种子投递成功后先建立内部下载任务记录；下载器首次返回真实文件列表时，为每个媒体文件生成命名计划，不等待下载完成。
- 磁力元数据未就绪时只保留任务记录并显示“暂无文件信息”，不创建虚假媒体文件或命名计划。
- 媒体文件使用“AutoBangumi 内部下载任务 ID + 下载器文件序号”作为稳定身份；原始、当前和目标路径均为可更新属性。
- 逐文件缺省解析结果在首次生成计划时冻结；解析器升级不静默刷新既有快照，用户可显式“重新解析”，手动字段始终不被覆盖。
- 分组元数据、规则值和当前命名模板实时参与目标名称预览。
- 下载器任务消失时保留命名计划和手动字段，并提示无法应用；同内容 hash 的任务重新出现时恢复关联。
- 只有用户明确删除 AutoBangumi 下载记录时，才级联删除其命名计划。
- 尚未执行的命名计划自动采用最新计划修订；已经命名完成的文件遇到元数据或模板变化时，只展示新目标和差异，用户确认应用后才重新命名。
- 用户已确认应用的同一计划修订可在失败后自动重试，不需要重复确认。
