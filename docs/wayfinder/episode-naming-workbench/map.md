# 剧集命名工作台

## Destination

形成一份可直接进入开发的“剧集命名工作台”规格：明确合并剧集页、逐文件命名计划、缺省/手动字段来源、异常判断、重新命名行为及其数据边界。

## Notes

- 领域词汇以 [CONTEXT.md](../../../CONTEXT.md) 为准。
- 逐项决策时使用 `grilling` 与 `domain-modeling`；交互结构使用 `prototype` 验证。
- 本地图默认只产出决策和规格，不实施功能。
- 后续测试和运行必须在 WSL 中执行。

## Decisions so far

- [确定剧集命名工作台的产品边界](./000-product-boundary.md) — 番剧卡片进入跨规则合并的逐文件命名页，以缺省/手动字段组合最终名称，并支持持久纠错后重新命名。
- [确定番剧分组的稳定身份](./001-group-identity.md) — 稳定分组 ID 统一作品元数据，成员规则保留来源行为，并可通过移动规则纠正合并或拆分。
- [确定命名计划的生成与存续周期](./002-plan-lifecycle.md) — 文件列表就绪即生成稳定计划，冻结缺省解析并保护手动值，历史目标变化需明确应用。
- [确定命名字段的完整性与异常规则](./003-completeness.md) — 当前命名规则引用即必需，统一异常给出可操作原因，并按媒体文件隔离失败。
- [确定手动应用的原子边界与失败恢复](./004-apply-boundary.md) — 视频与字幕作为命名单元预检并前向恢复，冲突不覆盖，已确认修订持久重试。
- [验证合并剧集页的交互结构](./005-ui-prototype.md) — 采用逐文件剧集表格，行内展开动态字段编辑，并就地呈现来源、目标预览和异常。
- [确定既有规则的番剧分组迁移策略](./006-group-migration.md) — 仅自动合并强身份键完全一致的规则，其余建立独立分组并标记待确认，旧规则 ID 与下载器关联保持不变。
- [确定既有媒体文件的命名计划回填策略](./007-existing-plan-backfill.md) — 当前路径作为中性既有基线，回填只生成预览且不把历史未知状态误判为手动或在升级时批量改名。
- [确定自动与手动重命名的并发协调](./008-rename-coordination.md) — 所有入口共用按命名单元的修订租约与栅栏，过期执行者只能记录实际结果并在安全边界退出。
- [确定字幕与视频的稳定关联规则](./009-subtitle-association.md) — 仅在类型、季度、集数或唯一主干能够证明时关联字幕，歧义保持异常并允许人工指定。

## Completion

- 产品边界、稳定身份、计划生命周期、异常、应用原子性、迁移、回填、并发和字幕关联均已确定，可以进入正式实现。
- qBittorrent 与 aria2 必须共享领域语义，并分别通过文件序号稳定性、离线恢复、幂等改名、合集字幕和部分失败测试。

## Out of scope

- 页面不展示下载进度、暂停、做种等下载器状态。
- 不在逐文件表单中重复编辑来自番剧、规则或下载任务的字段。
- 不通过单集纠错修改番剧规则的季度或集数偏移。
