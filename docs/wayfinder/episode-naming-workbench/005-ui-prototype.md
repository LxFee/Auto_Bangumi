# 验证合并剧集页的交互结构

## Question

合并剧集页如何以最低认知负担呈现种子、视频文件、动态字段、缺省/手动来源、最终名称预览和异常，并让用户安全地编辑、应用或恢复？

## Resolution

采用方案 A“剧集表格”作为正式实现方向：

- 页面以逐文件表格为主体，在同一视线内展示集数、来源规则、缺省/手动状态、异常和目标名称预览。
- 点击一行后就地展开，只编辑需要从该文件名解析的动态字段；番剧、规则和下载任务已有字段不重复展示。
- 字段修改后立即更新组合结果；缺少当前模板必需字段时在对应行显示可操作的异常原因，并阻止该文件应用。
- 保留“恢复缺省”和“应用”操作，但正式实现必须接入已确定的命名计划修订与命名单元语义，不能直接沿用原型代码。
- 方案 B“异常优先”和方案 C“左右主从”不采用：前者弱化正常剧集的整体可见性，后者增加选择与视线切换成本。

完整三方案原型作为设计依据保存在 `codex/prototype-episode-naming-workbench` 分支；主分支只保留本决策，正式页面需重新实现。
